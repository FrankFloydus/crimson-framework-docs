## Build a trusted host

Use a separate server or operator project for publisher operations. The default addon supplies the client and game bindings. Publisher bindings require an opt-in build and can run in headless Godot without initializing the signed-in Steam client.

From the framework checkout root, build for the target you will run. This example uses Debug. Set the target to `template_release` for a Release build.

```powershell
Set-Location framework
scons platform=windows arch=x86_64 target=template_debug steam_publisher=yes
```

SCons stages the trusted DLL under `framework/bin/publisher/windows`. CMake uses `-DCRIMSON_STEAM_PUBLISHER=ON` and stages it under the selected build directory. Use the trusted DLL in your backend's addon. Keep publisher test transports and credentials out of production client exports. [Trusted build guide](https://github.com/FrankFloydus/crimson-framework/blob/v0.0.3/framework/docs/STEAM_PUBLISHER.md)

## Resolve the publisher key on the backend

Attach a [SteamPublisherHost](/api/classes/SteamPublisherHost) to your persistent backend scene root. Implement its secret resolver against your backend's secret store. This example uses an environment variable supplied only to the backend process.

```gdscript
extends SteamPublisherHost

func _resolve_secret(reference: StringName) -> String:
    if reference == &"MY_GAME_STEAM_PUBLISHER_KEY":
        return OS.get_environment(String(reference))
    return ""
```

Pass a reference to the key through the settings. With the resolver script attached to a child named `PublisherHost`, boot the publisher from its scene parent after both nodes enter the tree.

```gdscript
var settings := SteamPublisherSettings.new()
settings.app_id = configured_app_id
settings.host = $PublisherHost
settings.publisher_key_ref = &"MY_GAME_STEAM_PUBLISHER_KEY"
var started := SteamPublisher.boot(settings)
if started.ok:
    publisher = started.value
```

Crimson resolves the secret per request and sends it to Valve in `X-WebAPI-Key` over verified TLS. Use a key with the Steamworks permissions required by your AppID and operations. Keep keys, encrypted ticket material, and ticket bytes out of client builds, logs, saves, and replays. [SteamPublisherSettings](/api/classes/SteamPublisherSettings) · [Valve publisher keys](https://partner.steamgames.com/doc/webapi_overview/auth)

## Verify a player and their license

On the game client, request a Web API ticket with `await steam.auth().web_ticket("game-profile")`. After checking `ok`, send the ticket bytes to your backend over its authenticated connection. Close the ticket after the backend completes the exchange.

On the backend, verify the ticket with the same AppID and audience and use the verified identity for an ownership lookup. Attach the identity to the backend session that owns this player.

```gdscript
var verified: SteamIdentityResult = await publisher.auth().verify(ticket_bytes, "game-profile")
if verified.ok:
    var license: SteamAppOwnershipResult = await publisher.auth().owns_app(
        verified.value, configured_app_id
    )
    if license.ok and license.value.owns_app:
        profile_sessions.attach_authenticated_player(verified.value)
```

Your game still decides which actions that player may take. Use the backend session identity when submitting a score from a verified ranked run. For encrypted AppTicket verification, use [SteamOwnership](/api/classes/SteamOwnership) with the app's restricted SDK Auth key and a durable one-use challenge store. [SteamPublisherAuth](/api/classes/SteamPublisherAuth) · [Valve ownership verification](https://partner.steamgames.com/doc/features/auth)

## Process Steam Wallet orders

Enable microtransactions for your authorized AppID and provide a trusted [SteamPurchaseStore](/api/classes/SteamPurchaseStore) before you boot. Bind your game's authenticated commerce adapter to its Steam provider. The backend authenticates the buyer, validates the cart, and owns pricing and fulfillment.

1. Read buyer context with `await publisher.purchases().buyer_info(player)` before pricing a new checkout.
2. Use `begin(player, cart, checkout_id)` to reserve the quote. Persist it in the store. Reuse the same checkout ID and cart when retrying an ambiguous response.
3. Treat client authorization as a prompt to check Steam. Use `finalize(order_id)` from the backend. The store atomically persists the new order revision and applies the entitlement difference or records it in a durable outbox.
4. Run `reconcile()` with a persisted cursor to recover pending orders and process reversals. Reconciliation can repeat rows. Commit entitlements idempotently by order and item. A partial reversal removes the affected items.

Use `SteamPublisherSettings.SANDBOX` to exercise the Wallet flow with Valve's sandbox for your AppID. Check the API contracts for the store, charge confirmation, and refund authorization before granting real items. [SteamPublisherPurchases](/api/classes/SteamPublisherPurchases) · [Valve microtransactions](https://partner.steamgames.com/doc/features/microtransactions/implementation)

## Use other publisher services

| Feature | Backend responsibility |
| --- | --- |
| [Leaderboards](/api/classes/SteamPublisherLeaderboards) | Submit the score only after validating the run against your game rules. |
| [Inventory](/api/classes/SteamPublisherInventory) | Authorize mutations and verify the reported account and items. |
| [Game Notifications](/api/classes/SteamNotificationStore) | Durably claim one opt-in request per player launch. When a client opens a Steam session link, verify the player's membership before restoring the session. |
| [Moderation](/api/classes/SteamPublisherModeration) | Authorize the report and duration before submitting a suspension or permanent ban. |

Use the [publisher mock suite](/steam/testing#verify-publisher-operations) to exercise these flows with controlled inputs. Run live publisher tests with a production trusted build, a test AppID you administer, and permission to use the selected feature.
