Publisher operations belong in your backend. It verifies players, authorizes orders, and holds the Steamworks credentials those operations require.

## Install the publisher addon

If you have the separate trusted publisher addon, install it in a dedicated Godot project for your backend or operator tools. Use the standard Crimson addon in your game client. The publisher backend can run in headless Godot without a signed-in Steam client. [Installation](/installation)

## Resolve the publisher key on the backend

Set [`publisher_key_ref`](/api/classes/SteamPublisherSettings/properties/publisher_key_ref) to the name your backend uses to identify its Steamworks key. Implement [`_resolve_secret()`](/api/classes/SteamPublisherHost/methods/_resolve_secret) to load that key from your backend's secret storage. The example below reads the process environment. Crimson resolves the secret per request and sends it to Valve in `X-WebAPI-Key` over verified TLS. Use a key with the Steamworks permissions required by your AppID and operations. Keep keys, encrypted ticket material, and ticket bytes out of client builds, logs, saves, and replays. [Valve publisher keys](https://partner.steamgames.com/doc/webapi_overview/auth)

## Verify a player and their license

### Set up the backend

The backend script runs on a persistent `Node`. Set `steam_app_id` to your app and supply `MY_GAME_STEAM_PUBLISHER_KEY` in the backend process environment. The script creates a [`SteamPublisherHost`](/api/classes/SteamPublisherHost) and calls [`SteamPublisher.boot(settings)`](/api/classes/SteamPublisher/methods/boot) once the host enters the tree.

```gdscript
extends Node

class PublisherHost extends SteamPublisherHost:
    const KEY_REFERENCE: StringName = &"MY_GAME_STEAM_PUBLISHER_KEY"

    func _resolve_secret(reference: StringName) -> String:
        if reference != KEY_REFERENCE:
            return ""
        return OS.get_environment(String(reference))

const TICKET_AUDIENCE: String = "game-profile"

@export var steam_app_id: int

var _publisher: SteamPublisher


func _ready() -> void:
    if steam_app_id <= 0:
        push_error("Assign your Steam AppID in the Inspector.")
        return

    var host: PublisherHost = PublisherHost.new()
    add_child(host)

    var settings: SteamPublisherSettings = SteamPublisherSettings.new()
    settings.app_id = steam_app_id
    settings.host = host
    settings.publisher_key_ref = PublisherHost.KEY_REFERENCE

    var started: SteamPublisherResult = SteamPublisher.boot(settings)
    if not started.ok:
        push_error("Steam publisher startup failed: %s" % started.message)
        return

    _publisher = started.value


func verify_player(ticket_bytes: PackedByteArray) -> SteamIdentity:
    if _publisher == null or ticket_bytes.is_empty():
        return null

    var auth: SteamPublisherAuth = _publisher.auth()
    if auth == null:
        return null

    var verified: SteamIdentityResult = await auth.verify(ticket_bytes, TICKET_AUDIENCE)
    if not verified.ok:
        return null

    var identity: SteamIdentity = verified.value
    var license: SteamAppOwnershipResult = await auth.owns_app(identity, steam_app_id)
    if not license.ok or license.value == null or not license.value.owns_app:
        return null

    return identity
```

When your backend receives a ticket, pass its bytes to `await verify_player(ticket_bytes)`. The function calls [`verify()`](/api/classes/SteamPublisherAuth/methods/verify) with the expected audience and checks the current license with [`owns_app()`](/api/classes/SteamPublisherAuth/methods/owns_app). Attach a returned `SteamIdentity` to that player's backend session and return `true` to the client. If verification returns `null`, reject the request and return `false`.

### Request a ticket on the client

The client script runs on a persistent `Node` with the same `steam_app_id` as the backend. If the game already owns a Steam attachment, set `use_game_scope` to `true` and call `bind_game(game)` after boot. In your sign-in flow, await `verify_with_backend(send_ticket)`. The callable sends the bytes over your authenticated connection and returns `true` when the backend accepts the player.

The script requests a [Web API ticket](/api/classes/SteamAuth/methods/web_ticket) for `game-profile`, checks [`ok`](/api/classes/SteamResult/properties/ok), sends the [ticket bytes](/api/classes/SteamWebTicket/methods/bytes), and [closes the ticket](/api/classes/SteamWebTicket/methods/close) when the exchange finishes.

```gdscript
extends Node

const TICKET_AUDIENCE: String = "game-profile"

@export var steam_app_id: int
@export var use_game_scope: bool = false

var _steam: Steamworks


func _ready() -> void:
    if use_game_scope:
        return
    if steam_app_id <= 0:
        push_error("Assign your Steam AppID in the Inspector.")
        return

    var settings: SteamConfig = SteamConfig.new()
    settings.app_id = steam_app_id
    _steam = Steamworks.boot(self, settings)
    var startup: SteamResult = _steam.boot_result()
    if not startup.ok:
        push_error(startup.message)


func bind_game(game: Game) -> void:
    if use_game_scope and game != null:
        _steam = game.steam()
        if _steam.get_app_id() != steam_app_id:
            _steam = null
            push_error("The game's Steam AppID must match the backend.")


func verify_with_backend(send_ticket: Callable) -> bool:
    if _steam == null or not _steam.is_ready() or not send_ticket.is_valid():
        return false

    var auth: SteamAuth = _steam.auth()
    if auth == null:
        return false

    var issued: SteamWebTicketResult = await auth.web_ticket(TICKET_AUDIENCE)
    if not issued.ok or issued.value == null:
        return false

    var ticket: SteamWebTicket = issued.value
    var payload: PackedByteArray = ticket.bytes()
    if payload.is_empty():
        ticket.close()
        return false

    var accepted: bool = await send_ticket.call(payload)
    ticket.close()
    return accepted
```

Your game still decides which actions that player may take. Use the backend session identity when submitting a score from a verified ranked run. For encrypted AppTicket verification, call [`SteamPublisherAuth.verify_ownership()`](/api/classes/SteamPublisherAuth/methods/verify_ownership) with the expected challenge. Configure the app's restricted SDK Auth key and a durable one-use challenge store. A successful result contains a [`SteamOwnership`](/api/classes/SteamOwnership) receipt. [Valve ownership verification](https://partner.steamgames.com/doc/features/auth)

## Process Steam Wallet orders

Enable microtransactions for your authorized AppID. Before booting the publisher, assign your trusted [SteamPurchaseStore](/api/classes/SteamPurchaseStore) to [`purchase_store`](/api/classes/SteamPublisherSettings/properties/purchase_store). For an existing SteamProvider integration, use [`with_commerce_backend()`](/api/classes/SteamProvider/methods/with_commerce_backend) with your authenticated [`SteamCommerceBackend`](/api/classes/SteamCommerceBackend) adapter. The backend authenticates the buyer, validates the cart, and owns pricing and fulfillment.

1. Get the [`purchases()`](/api/classes/SteamPublisher/methods/purchases) service and call [`buyer_info(player)`](/api/classes/SteamPublisherPurchases/methods/buyer_info) before pricing a new checkout.
2. Use [`begin(player, cart, checkout_id)`](/api/classes/SteamPublisherPurchases/methods/begin) to price and reserve the cart through the store. Reuse the same checkout ID and cart when retrying an ambiguous response.
3. Treat client authorization as a prompt to check Steam. Use [`finalize(order_id)`](/api/classes/SteamPublisherPurchases/methods/finalize) from the backend. The store atomically persists the new order revision and applies the entitlement difference or records it in a durable outbox.
4. Run [`reconcile(since_unix)`](/api/classes/SteamPublisherPurchases/methods/reconcile) with a persisted Unix UTC cursor to recover pending orders and process reversals. Persist the returned [`next_since_unix`](/api/classes/SteamPurchaseReconciliation/properties/next_since_unix) on success and keep the current cursor on failure. Reconciliation can repeat rows. Commit entitlements idempotently by order and item. A partial reversal removes the affected items.

Set [`environment`](/api/classes/SteamPublisherSettings/properties/environment) to [`SteamPublisherSettings.SANDBOX`](/api/classes/SteamPublisherSettings#environment) before boot to exercise the Wallet flow with Valve's sandbox for your AppID. Check the API contracts for the store, charge confirmation, and refund authorization before granting real items. [SteamPublisherPurchases](/api/classes/SteamPublisherPurchases) · [Valve microtransactions](https://partner.steamgames.com/doc/features/microtransactions/implementation)

## Use other publisher services

| Feature | Backend responsibility |
| --- | --- |
| [Leaderboards](/api/classes/SteamPublisherLeaderboards) | Submit the score only after validating the run against your game rules. |
| [Inventory](/api/classes/SteamPublisherInventory) | Authorize mutations and verify the reported account and items. |
| [Game Notifications](/api/classes/SteamNotificationStore) | Use [`request_opt_in()`](/api/classes/SteamGameNotifications/methods/request_opt_in) with a durable claim keyed by app, account, and authoritative launch ID. When a client opens a Steam session link, verify the player's membership before restoring the session. |
| [Moderation](/api/classes/SteamPublisherModeration) | Authorize the report and duration before submitting a suspension or permanent ban. |

Verify your backend using your AppID, a Steam test account, and credentials authorized for the feature you use. Start with a license check. Test purchases in Valve's sandbox before you enable live fulfillment. [Verify publisher operations](/steam/testing#verify-publisher-operations)
