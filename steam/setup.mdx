Install Crimson in your Godot project before adding Steam. The setup is the same whether you want achievements for a solo game or a lobby for multiplayer. [Installation](/installation)

## Add the Steam runtime

1. Obtain Valve's Steamworks SDK. Crimson v0.0.3 was verified with SDK 1.65. [Steamworks SDK](https://partner.steamgames.com/doc/sdk)
2. Copy `redistributable_bin/win64/steam_api64.dll` from the SDK into `addons/crimson-framework/bin/` in your Godot project. Put it beside the Crimson DLLs.
3. Start Steam and sign in. Launch Steam and Godot under the same Windows account and with the same administrator privileges.

## Launch with an AppID

Steam supplies your AppID when you launch an installed game from the Steam Library. For a development launch, use a separate copy of Godot or a test export. Put a plain text file named `steam_appid.txt` beside the executable. Write only the AppID into the file and launch with that directory as the working directory. [Valve's initialization guide](https://partner.steamgames.com/doc/sdk/api#SteamAPI_Init)

You can use Valve's Spacewar AppID `480` for a first connection check. Use your own AppID and a Steam test account with a license for your app to verify your achievements, Cloud settings, ownership, or purchases. [Valve's Spacewar example](https://partner.steamgames.com/doc/sdk/api/example)

Run the first client example with the same AppID. It prints the game's Steam language and whether the client is online. [Start a Steam client](/steam/client-services#start-a-client)

## Export and verify on Windows

In your Windows export preset, add `crimson_steam` to **Custom Features**. Godot then includes `steam_api64.dll` beside the exported executable. If you also ship a direct ENet version without Steam, leave `crimson_steam` out of that export preset. Keep `steam_appid.txt` for local development and leave it out of your Steam depot. [Godot GDExtension dependencies](https://docs.godotengine.org/en/4.7/engine_details/engine_api/gdextension/gdextension_file.html#dependencies)

Test your Debug export and your Release export. For the distribution check, put the final export on a private Steam branch. Install that build through the Steam Library with an entitled test account and verify startup, your app's features, and Overlay behavior. [SteamPipe upload](https://partner.steamgames.com/doc/sdk/uploading)

### Relaunch an unwrapped export through Steam

If your unwrapped game should launch through Steam even when opened from its executable, call [`SteamClient.restart_through_steam_if_needed(app_id)`](/api/classes/SteamClient#restart_through_steam_if_needed) at your common startup entry point, before initializing any Steam service. Quit the current process on `ERR_SKIP` so Steam can launch the installed copy. Proceed with Steam startup on `OK` and surface any other error. Use your authorized shipping AppID. [Valve's relaunch check](https://partner.steamgames.com/doc/sdk/api#SteamAPI_RestartAppIfNecessary)

### Wrap an export for Steam DRM

If you use Valve's optional DRM wrapper, follow Valve's SteamPipe instructions to wrap the exported game executable for your AppID. Keep the wrapped executable with its companion files. The wrapper handles Steam relaunch, so you can leave the separate relaunch call out of the wrapped export. Install the build from a private Steam branch to verify it. [Steam DRM](https://partner.steamgames.com/doc/features/drm)
