Use the transaction coordinator to prepare, validate, and publish changes across game state stores. Player bindings map admitted peers to stable player IDs, possession tracks primary control, and the command router checks the match and player context before calling your gameplay handler.

## Classes

| Class | Purpose |
| --- | --- |
| [`CommandRouter`](/api/classes/CommandRouter) | Dispatches validated gameplay intents on the authority using player identities resolved by trusted ingress. |
| [`GameTransaction`](/api/classes/GameTransaction) | A single-use plan owned by a `TransactionCoordinator`. |
| [`PlayerBindings`](/api/classes/PlayerBindings) | Maps admitted transport peers to stable player IDs, with at most one live peer per player. |
| [`PlayerPossession`](/api/classes/PlayerPossession) | Maintains the authoritative primary-control assignment. |
| [`TransactionCoordinator`](/api/classes/TransactionCoordinator) | Owns authoritative dictionary stores and publishes prepared changes together at a single commit revision. |
