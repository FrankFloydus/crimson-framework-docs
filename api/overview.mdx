This reference covers the Godot scripting API in Crimson Framework v0.0.3. Open a module to see what it does, which classes it exposes, and which enums those classes define. Each class page describes its purpose, shows its inheritance, and lists the members it defines.

For a step-by-step example, start with [your first solo game](/quickstart) or the [Steamworks guides](/steam/overview).

## Modules

| Module | Use it to |
| --- | --- |
| [Game runtime](/api/modules/game-runtime) | Configure, start, and run a game with world transitions and checkpoints. |
| [World sessions](/api/modules/world-sessions) | Mount one shared world and manage player spawning and local views. |
| [Sessions and transport](/api/modules/sessions-and-transport) | Host and join sessions, admit peers, and choose a transport. |
| [Scene loading](/api/modules/scene-loading) | Prepare scenes and coordinate when they become active. |
| [Match runtime](/api/modules/match-runtime) | Bind players to characters and apply authoritative gameplay changes. |
| [Replication](/api/modules/replication) | Distribute committed state to the players who can see it. |
| [Inventory](/api/modules/inventory) | Manage grid items, containers, equipment, and trades. |
| [Save and restore](/api/modules/save-and-restore) | Store, inspect, and restore checkpoint generations. |
| [Steamworks](/api/modules/steamworks) | Use player services such as achievements, Cloud, Input, and Workshop. |
| [Steam multiplayer](/api/modules/steam-multiplayer) | Connect a Crimson game to Steam lobbies, invites, and dedicated servers. |
| [Steam publisher](/api/modules/steam-publisher) | Verify player ownership and run authorized publisher operations from a trusted backend. |

## Read a class page

Expand a module in the sidebar, open a class, then expand **Properties** or **Methods**. For example, open [Game runtime](/api/modules/game-runtime), choose [`GameRuntime`](/api/classes/GameRuntime), and follow [`play_solo()`](/api/classes/GameRuntime/methods/play_solo). Follow **Inherits** on a class page to find members of its base class when that class is also part of Crimson.

Each property page shows its type, access, any documented default, and a GDScript example. Each method page shows its signature, any parameters and return value, and an example. Signals, enums, and constants are listed on their declaring class.

The return value section explains how to receive an asynchronous result. Some methods return an operation and ask you to await its [`wait()`](/api/classes/GameOperation/methods/wait) method. Others, such as [`web_ticket()`](/api/classes/SteamAuth/methods/web_ticket), can be awaited directly.
