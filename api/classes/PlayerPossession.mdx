**Inherits** `RefCounted`

Maintains the authoritative primary-control assignment. Each player has at most one primary character and each character has at most one primary controller. Switches, releases, and optional game eligibility rules run through the match transaction coordinator.

## Methods

### `configure`

`configure(coordinator: TransactionCoordinator, players_store: String, characters_store: String, eligibility: Callable = Callable()) -> Error`

Registers possession state and its validator on the given coordinator. Supply two distinct, already registered stores containing dictionaries keyed by player and character ID. The optional `eligibility(player\_id, old\_id, new\_id, context)` callback returns whether the proposed change is allowed.

### `get_controller`

`get_controller(character_id: String) -> String`

Returns the committed player ID controlling the character as primary, or an empty string.

### `get_primary`

`get_primary(player_id: String) -> String`

Returns the player's committed primary character ID, or an empty string.

### `get_revision`

`get_revision(player_id: String) -> int`

Returns the revision of the player's committed assignment, or zero if no assignment record is available.

### `queue_primary_change`

`queue_primary_change(transaction: GameTransaction, player_id: String, character_id: String, expected_revision: int) -> Error`

Adds a switch or release to a transaction from the configured coordinator. Pass an empty `character\_id` to release and use the last observed assignment revision as `expected\_revision`. The coordinator checks the assignment when the transaction commits.

### `try_set_primary`

`try_set_primary(player_id: String, character_id: String, expected_revision: int) -> Dictionary`

Creates and commits a transaction for one primary switch or release. Pass an empty `character\_id` to release and supply the last observed assignment revision. Returns a transaction outcome with `ok`, `code`, `message`, and `revision`.

## Signals

### `primary_changed`

`primary_changed(player_id: String, old_id: String, new_id: String, revision: int)`

Emits after publication when the player's primary character ID changes. The old and new IDs use empty strings for unassigned control. The revision belongs to the new assignment record.
