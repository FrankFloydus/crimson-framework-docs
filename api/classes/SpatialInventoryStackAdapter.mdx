### Method details

#### `commit_detached_split`

`commit_detached_split(plan: Dictionary, claim_cursor: Callable) -> Error`

Recheck and commit a split through the record callback. The `claim_cursor` callable receives no arguments and returns a Godot Error. Use it to claim the newly created stack in the game's cursor or held-item model.

#### `commit_merge`

`commit_merge(plan: Dictionary, commit_placement: Callable = Callable()) -> Error`

Recheck the merge plan against current records and commit the quantities through the host callback. Pass an optional no-argument placement callback returning a Godot Error to pair the record changes with placement changes.

#### `commit_split`

`commit_split(plan: Dictionary, destination: SpatialInventory, footprint: Vector2i, origin: Vector2i, rotated: bool = false) -> Error`

Recheck the split plan, then create the new stack and place it in the destination at the given origin and rotation. Pass its unrotated footprint.

#### `get_apply_changes`

`get_apply_changes() -> Callable`

Return the host callback that stages and commits stack record changes.

#### `get_describe_stack`

`get_describe_stack() -> Callable`

Return the callback used to look up current stack records.

#### `get_merge_capacity`

`get_merge_capacity(id: StringName, key: StringName) -> int`

Return the remaining capacity of the stack if its compatibility key matches `key`, otherwise return 0.

#### `get_split_limits`

`get_split_limits(id: StringName) -> Dictionary`

Return an `error` code and, on success, the current `quantity` and `max_amount` available for a split. A split leaves at least one unit in the source.

#### `get_stack_key`

`get_stack_key(id: StringName) -> StringName`

Return the current compatibility key, or an empty StringName if the stack record is unavailable or invalid.

#### `get_stack_records_revision`

`get_stack_records_revision() -> int`

Return the revision tracking changes to the host-owned stack records.

#### `invalidate_stack_records`

`invalidate_stack_records() -> void`

Advance the record revision after the host updates quantities or stack records outside the adapter.

#### `plan_merge`

`plan_merge(source_id: StringName, target_id: StringName, limit: int = 0) -> Dictionary`

Read the source and target records and build a checked merge plan for compatible stacks. A positive `limit` caps the units moved. Returns an `error` code and, on success, a plan with `moved`, `remaining`, and `changes`.

#### `plan_split`

`plan_split(source_id: StringName, new_id: StringName, amount: int) -> Dictionary`

Plan a transfer of part of the source quantity to an unused `new_id`. The amount must be positive and less than the source quantity. Returns an `error` code and, on success, a plan for one of the split commit methods.

#### `set_apply_changes`

`set_apply_changes(value: Callable) -> void`

Set the callback taking expected record edits and a placement commit callable. It verifies and stages the edits, calls the commit synchronously when provided, and rolls back the staged records if that call fails.

#### `set_describe_stack`

`set_describe_stack(value: Callable) -> void`

Set the callback taking an item ID and returning `key`, `quantity`, and `max_quantity`, or an empty dictionary when no stack record exists.
