**Inherits** `RefCounted`

Owns authoritative dictionary stores and publishes prepared changes together at a single commit revision. Store preparers and cross-store validators operate on detached data. Use the coordinator on the thread that created it and keep callbacks free of external side effects.

## Methods

### `begin`

`begin(context: Dictionary = {}) -> GameTransaction`

Creates a writable transaction with a detached copy of the authority's `context`. Returns `null` if called from another thread, during protected mutation, or with an unsupported context.

### `capture_snapshot`

`capture_snapshot() -> Dictionary`

Captures the entire store registry at one revision. On success, read the detached store map from the result's `stores` field. The result also carries `ok`, `code`, `message`, and `revision`.

### `commit`

`commit(transaction: GameTransaction) -> Dictionary`

Submits a transaction owned by this coordinator. Checks each expected store revision, prepares candidates, validates them, and publishes every changed store before notification. Returns `ok`, `code`, `message`, and `revision`. A failed evaluation consumes the submitted transaction and leaves all committed states and revisions intact.

### `get_revision`

`get_revision() -> int`

Returns the coordinator's global commit revision, or `-1` from another thread.

### `get_store_revision`

`get_store_revision(store_id: String) -> int`

Returns the store's current committed revision, or `-1` when the store is unknown or accessed from another thread.

### `notify_restore_published`

`notify_restore_published(published_revision: int) -> Error`

Emits the deferred `committed` notification for the matching published revision. Mutation remains gated until observers return. An absent or mismatched pending revision returns `ERR\_INVALID\_PARAMETER`.

### `prepare_restore`

`prepare_restore(snapshot: Dictionary, context: Dictionary = {}) -> Dictionary`

Validates a detached store map with exactly the registered store IDs. On success, the result's `candidate` field contains a single-use `GameTransaction` for `publish\_restore()`. Live stores stay readable at their current committed revision during preparation.

### `publish_restore`

`publish_restore(candidate: GameTransaction, defer_notification: bool = false) -> Dictionary`

Publishes the candidate to all registered stores and advances the coordinator revision. Changes to the registry or revision since preparation make a candidate stale. Set `defer\_notification` to hold the `committed` signal and mutation gate until `notify\_restore\_published()`. Returns `ok`, `code`, `message`, and `revision`.

### `read_store`

`read_store(store_id: String) -> Dictionary`

Returns a detached copy of the last committed state. Returns an empty dictionary for an unknown store or when called from another thread.

### `register_store`

`register_store(store_id: String, initial_state: Dictionary, prepare: Callable, validate_restore: Callable = Callable()) -> Error`

Registers a unique store ID, detached initial dictionary, and `prepare(current, operations, context)` callback. Preparation returns a dictionary with boolean `ok`, a dictionary `state` on success, and an optional `message`. The optional `validate\_restore(candidate, context)` callback returns boolean `ok` in a dictionary and can include `message`. Without it, restore calls the preparer with an empty operation array.

### `register_validator`

`register_validator(validator_id: String, watched_stores: PackedStringArray, validator: Callable) -> Error`

Registers a unique validator over existing `watched\_stores`. The `validator(prepared, context)` callback receives detached candidates for changed stores. Read unchanged stores through the coordinator. Return a dictionary with boolean `ok` and an optional `message`.

## Signals

### `committed`

`committed(revision: int, stores: PackedStringArray)`

Emits after every prepared state is installed. The `revision` is the new coordinator revision and `stores` lists the changed store IDs. Observers can read committed data while nested mutation stays gated.
