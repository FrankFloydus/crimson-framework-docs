---
title: "SaveCoordinator"
description: "A scene-tree node that coordinates checkpoint capture, storage, inspection, and staged restore. Configure it and submit requests on the main thread. Keep the host and participant adapters alive for the duration of their tickets. Capture, migration, and restore callbacks run on the main thread, and storage and codec work run on a worker using detached data. Save, load, and inspection requests return a positive ticket when admitted or 0 on rejection. Profile and slot IDs use 1 to 64 lowercase ASCII letters, digits, underscores, or hyphens, with a letter or digit first. App, scope, and participant IDs also allow periods after the first character. The first admitted ticket freezes app and storage configuration. The first admitted save or load also freezes the scope and schema registrations."

## Signals

### `load_prepared`

`load_prepared(ticket: int, generation: Dictionary)`

Emitted on the main thread after an explicit prepare request finishes staging and linking. The generation dictionary contains `sequence` and `id`. The ticket remains active until you activate or cancel it.

### `operation_finished`

`operation_finished(ticket: int, result: Dictionary)`

Emitted on the main thread when a ticket reaches a terminal result. The dictionary includes `ok` and `code` and can include `message`, `warning`, or `value`. Successful saves and loads return the generation's `sequence` and `id` in `value`.

### `operation_progress`

`operation_progress(ticket: int, phase: String)`

Emitted on the main thread when a ticket changes phase. Several transitions can arrive in one frame. A `Verifying` update during load gives listeners a chance to cancel before main-thread restore work.
