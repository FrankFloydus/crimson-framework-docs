## Description

Inject the implementation through `SteamPublisherSettings.notification_store`. Use durable storage that applies the operation key, fingerprint, target reservation, and ownership decisions across backend workers.

## Methods

### Virtual methods

#### [`_claim`](/api/classes/SteamNotificationStore/methods/_claim)

Atomically compare the app-scoped key and fingerprint, replay completed receipts, and claim a new write only when authorized.

#### [`_claim_launch_opt_in`](/api/classes/SteamNotificationStore/methods/_claim_launch_opt_in)

Atomically reserve notification registration for the exact verified app, account, and authoritative launch ID across backend workers.

#### [`_commit`](/api/classes/SteamNotificationStore/methods/_commit)

Atomically commit the exact claim and its provider ID.

#### [`_owns_session`](/api/classes/SteamNotificationStore/methods/_owns_session)

Returns whether the trusted backend currently owns this provider session for the configured app.

#### [`_release_unsent`](/api/classes/SteamNotificationStore/methods/_release_unsent)

Atomically releases the exact claim and its target reservation when Crimson reports that transport scheduling failed.

#### [`_release_unsent_launch_opt_in`](/api/classes/SteamNotificationStore/methods/_release_unsent_launch_opt_in)

Release the exact launch claim when Crimson confirms no Steam request was scheduled.
