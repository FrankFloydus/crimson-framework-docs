## Description

Implement these synchronous hooks using durable storage in a trusted process. Partition records by AppID and environment. Scope checkout uniqueness to the authenticated account. A commit atomically persists the next revision and applies the matching entitlement difference, or records that difference in a durable outbox within the same transaction. Compute the desired paid item set from the incoming phase and reversed IDs, then compare it with the durable granted set. A first payment observation can be partial, so grant only surviving items in that case. Repeated commits and outbox delivery must be idempotent by order and item.
