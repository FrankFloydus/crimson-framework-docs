Crimson attaches a game to a node you already own, such as the `Main` node that also owns your menus. It creates a child named `Game` and mounts the active level beneath that attachment. Leave that child name available for Crimson. Keep your menus and game services outside the mounted level so they remain available when it unloads.

| Class | What it does |
| --- | --- |
| [`GameConfig`](/api/classes/GameConfig) | Describes the level, player, and optional services. [`boot(owner)`](/api/classes/GameConfig/methods/boot) attaches them to a node in the scene tree. |
| [`Game`](/api/classes/Game) | Gives your scripts a handle for starting play, reading session state, and leaving. |
| [`GameResult`](/api/classes/GameResult) | Reports success, a stable outcome code, and a message. Some actions also report the activated world or published online listing. |
| [`WorldDefinition`](/api/classes/WorldDefinition) | Gives a level a stable ID and scene path in a coordinated game. |

## Start and stop a training session

Create `res://training_room.tscn` with a `Node3D` root and a `Node3D` child named `SpawnPoints` containing one `Marker3D`. Create `res://training_player.tscn` with a `Node3D` root and a `Camera3D` child. Create a third scene with a `Node` root, attach this script, and run that scene. Press **P** to start play or **L** to leave. The script reports the transition in Godot's **Output**. Add a visible object and a light to the level if you want to see a change in the game window too.

```gdscript
extends Node

const LEVEL: PackedScene = preload("res://training_room.tscn")
const PLAYER: PackedScene = preload("res://training_player.tscn")
const PLAY_KEY: Key = KEY_P
const LEAVE_KEY: Key = KEY_L

var _game: Game
var _busy: bool = false


func _ready() -> void:
    _game = Game.configure(LEVEL, PLAYER).boot(self)
    var booted: GameResult = _game.boot_result()
    if not booted.ok:
        push_error(booted.message)
        set_process_unhandled_key_input(false)
        return

    print("Press P to play or L to leave.")


func _unhandled_key_input(event: InputEvent) -> void:
    var key: InputEventKey = event as InputEventKey
    if key == null or not key.pressed or key.echo or _busy:
        return

    if key.keycode == PLAY_KEY and _game.get_phase() == Game.IDLE:
        _busy = true
        var started: GameResult = await _game.play()
        _busy = false
        if started.ok:
            print("Training room ready.")
        else:
            push_error(started.message)
    elif key.keycode == LEAVE_KEY and _game.get_phase() == Game.RUNNING:
        _busy = true
        var left: GameResult = await _game.leave()
        _busy = false
        if left.ok:
            print("Training room closed. Press P to restart.")
        else:
            push_error(left.message)
```

[`boot_result()`](/api/classes/Game/methods/boot_result) reports whether configuration attached successfully. [`play()`](/api/classes/Game/methods/play) settles when play is ready or startup fails. [`leave()`](/api/classes/Game/methods/leave) retires the session, so **P** can start another one on the same attachment. Removing the owning node retires the attachment itself. ## Choose how worlds progress

Use [`Game.configure(level, player)`](/api/classes/Game/methods/configure) for a fixed world with automatic spawning. Use [`Game.campaign(start)`](/api/classes/Game/methods/campaign) when you want to register multiple worlds, coordinate gameplay commands, or save match state. Your game supplies its own actors and rules in a coordinated world. [Checkpoints](/checkpoints) · [Coordinated LAN](/coordinated-lan)
