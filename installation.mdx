## Requirements

- Godot 4.7 stable for Windows x86-64 with standard single precision. The release ZIP includes the native DLLs for the editor and for both debug and release exports. [Godot 4.7 downloads](https://godotengine.org/download/archive/4.7-stable/)
- A Godot project with a `project.godot` file.

You can run offline sessions and direct ENet multiplayer with the addon ZIP alone. Steam features need Valve's runtime, which you can add later. [Steam setup](/steam/overview)

## Install the addon

1. Close the Godot editor if the project is open. Download the Crimson addon ZIP from the release's **Assets** list. [Download the addon ZIP](https://github.com/FrankFloydus/crimson-framework/releases/download/v0.0.3/crimson-framework-0.0.3.zip) · [Release notes](https://github.com/FrankFloydus/crimson-framework/releases/tag/v0.0.3)
2. Extract `crimson-framework-0.0.3.zip` into the directory that contains `project.godot`. If the project already has an `addons/` directory, merge the directory and keep the other addons. Check the installed files against this layout.

   ```text
   your-game/
   ├── project.godot
   └── addons/
       └── crimson-framework/
           ├── crimson-framework.gdextension
           ├── crimson-framework.gdextension.uid
           ├── bin/
           │   ├── crimson_framework.windows.template_debug.x86_64.dll
           │   └── crimson_framework.windows.template_release.x86_64.dll
           ├── images/
           └── licenses/
   ```

3. Open the project in Godot and wait for it to scan the files. Godot loads the native extension from `crimson-framework.gdextension`. [Godot GDExtension descriptors](https://docs.godotengine.org/en/4.7/engine_details/engine_api/gdextension/gdextension_file.html)

## Verify the installation

Open or create a scene and open the **Add Child Node** dialog. Search for `GameRuntime`. If the class appears, Godot loaded the addon. Select it to inspect its properties or follow the quickstart to run a complete solo session. [Quickstart](/quickstart)

If `GameRuntime` is missing, check the editor **Output** for errors when it loads the extension. Confirm the descriptor and both DLLs are under the paths shown above and that you're running Godot 4.7 for Windows x86-64 with single precision. If Godot reports a duplicate class, check for an older Crimson descriptor or an earlier standalone inventory or save extension that registers the same class names.

## Update an existing project

Back up or commit the project, close Godot, and replace the `addons/crimson-framework/` directory with the copy from the new ZIP. Reopen the project and check that scripts and scenes load. If your project stages a Steam runtime, follow the Steam setup again to restore it. For projects that still use older class names such as `CrimsonGame`, follow the migration before reopening the project. [Godot class-name migration](https://github.com/FrankFloydus/crimson-framework/blob/v0.0.3/framework/docs/API_NAME_MIGRATION.md)

## Export for Windows

Install Godot 4.7's matching export templates through **Editor → Manage Export Templates**. In **Project → Export**, add a **Windows Desktop** preset with **Architecture** set to `x86_64`. Godot selects Crimson's debug or release DLL for the export. Keep the generated files together and run the exported game to verify it starts. [Godot export guide](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_projects.html)

For a Steam build, configure the optional DLL and export feature before exporting. [Steam setup](/steam/overview)

## Build from source

To rebuild the addon, use the source build instructions for MSVC, the Windows SDK, Python, and SCons or CMake. [Crimson Framework build instructions](https://github.com/FrankFloydus/crimson-framework/blob/v0.0.3/framework/README.md#build)
